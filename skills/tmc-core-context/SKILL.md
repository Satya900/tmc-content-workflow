# TMC Core Context

## Purpose
Keep every TMC output aligned with the same business positioning, audience logic, voice, content categories and factual boundaries.

## Before doing any TMC work
0. Read the repository's `brand-brief.md` for visual identity and caption rules. In a portable desktop pack, use the bundled TMC_CONTEXT.md instead. Read `system/WORKFLOW.md` for the current non-video operating scope when working in this repository.
1. Read `references/tmc-brand-context.md`.
2. If the task is content creation or planning, read `references/marketing-template-framework.md`.
3. If the task creates a marketing asset, apply `references/content-taxonomy.md`.
4. If the task contains factual claims, use the claims register if available and follow `references/claims-register-template.md`.

## Non-negotiables
- Distinguish TOUR content from MARKETING content before writing.
- Do not treat TMC as a generic travel operator.
- Do not invent TMC facts, school facts, student outcomes, testimonials, prices, safety claims or permissions.
- Prefer practical educational value over generic inspiration.
- Use one clear audience and one primary content job per asset.
- Human review is required before publication.

## When information is missing
Mark it clearly as `NEEDS INPUT`, `VERIFY`, or `SOURCE REQUIRED`.
Do not silently fill gaps.

## Output behaviour
When another TMC format skill is also relevant, use this skill as the shared context and let the format skill control the final structure.
