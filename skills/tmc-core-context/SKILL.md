# TMC Core Context

## Purpose
Keep every TMC output aligned with the same positioning, audience logic, content buckets, voice, content categories and factual boundaries.

## Before doing any TMC work
0. Read the repository's `brand-brief.md` for visual identity and caption rules. In a portable desktop pack, use the bundled TMC_CONTEXT.md instead. Read `system/WORKFLOW.md` for the current operating scope when working in this repository.
1. Read `references/tmc-brand-context.md` (positioning, objective, audience roles, programmes, SEL values, voice).
2. Read `references/content-buckets.md` and assign one primary bucket.
3. For content creation or planning, read `references/audience-personas.md`, `references/marketing-template-framework.md` (the 4D process and 33 angles) and `references/content-strategy-workbook.md` (the answered B2B workbook: buying committee, bucket research, needs and emotions per bucket, channel roles). Ready topics: `references/topic-bank.md`.
4. For a specific format or channel, read the relevant section of `references/content-generation-playbook.md`.
5. For a marketing asset, apply `references/content-taxonomy.md`.
6. For factual claims, use the claims register if available and follow `references/claims-register-template.md`.
7. For calendars, cadence or performance, read `references/measurement-and-calendar.md`.

## Non-negotiables
- TMC is B2B. The school is the customer. Every MARKETING asset is written for a school role. Parents and students are voices and evidence, never sales targets, and no CTA asks a family to act.
- Distinguish TOUR content from MARKETING content before writing.
- Position TMC as an educational experience design partner, never a generic travel operator.
- One primary audience and one primary content bucket per asset.
- Do not invent TMC facts, school facts, student outcomes, testimonials, prices, safety claims, founder anecdotes or permissions.
- TMC's selling points in its own planning documents are claims to verify, not facts.
- Internal planning data (targets, school segments, product funnel labels) is never published.
- Prefer practical educational value over generic inspiration.
- Human review is required before publication.

## When information is missing
Mark it clearly as `NEEDS INPUT`, `VERIFY` or `SOURCE REQUIRED`. Do not silently fill gaps.

## Output behaviour
When a format skill is also relevant, use this skill as the shared context and let the format skill control the final structure.
